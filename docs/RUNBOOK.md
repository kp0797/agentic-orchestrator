# Runbook

Everything below uses Docker from the repository root. The first build downloads Maven dependencies into
`./.m2` and takes a few minutes; later runs reuse it.

## Commands

| Goal | Command |
| --- | --- |
| Run the test suite | `docker compose run --rm test` (output also in `build.log`) |
| Engine demo with fake agents | `docker compose run --rm demo` |
| A scenario in the terminal | `docker compose run --rm smoke` / `brownfield` / `ambiguous` |
| The approval console | `docker compose up console` → http://localhost:8080 |
| Reliability across runs | `docker compose run --rm eval` (3 scenarios × 3 runs) |
| Verify an evidence pack | `docker compose run --rm smoke verify-evidence runs/<run>/evidence` |
| Run the shortener | `docker compose --profile shortener up shortener` → http://localhost:8081 |
| Metrics and alerts | `docker compose --profile shortener --profile observability up console shortener prometheus` → http://localhost:9090 |
| Audit log in PostgreSQL | `SPRING_PROFILES_ACTIVE=postgres docker compose up postgres console` |

Any orchestrator service accepts other CLI arguments after its name, for example
`docker compose run --rm smoke run brownfield --auto-approve --inject fix-alias-race:gate:build@1`.
`docker compose run --rm smoke help` lists every command.

## Operating a run in the console

1. **Start** a scenario from the home page. The console starts no scripted stakeholder: you answer.
2. **Approve or reject.** A node waiting for you shows *review*. The page shows the output, the diff,
   the gate results and why approval is needed. Enter your name; a rejection needs feedback, which
   becomes the agent's instruction for its next attempt. A decision applies only to the output digest you
   reviewed; if the output changed meanwhile, the console refuses it and asks you to review again.
3. **Clarify or change scope** (run page). Before execution, it answers the open questions and re-runs
   the requirements step. During execution, it stops the running plan, rolls back its work and re-plans;
   the plan comes back for approval as v2.
4. **Kill switch**: safe-stop. In-flight work is cancelled and recorded; **Resume** continues from the
   log without redoing finished nodes.
5. **Evidence**: the CLI writes `runs/<planning run>/evidence/` after every run; the eval harness writes
   one per run under `runs/eval-<time>/`.

## Budgets

Each scenario sets wall time, tokens and cost (`budget:` in `scenario.yaml`). A breach safe-stops the run
with `BUDGET_EXCEEDED`. To continue, raise the budget (`Engine.updateBudget`, recorded as
`BUDGET_UPDATED`) and resume.

## Recording a cassette

Needs an API key (see [LLM_AND_RUNTIME.md](LLM_AND_RUNTIME.md)). Record into the scenario's cassette:

```bash
AGENTIC_MODE=record docker compose --profile live up console-live
```

Start the scenario in the console and review each approval. Every exchange is appended to
`scenarios/<name>/cassette.jsonl` as it happens, so an interrupted recording keeps what it has; move a
partial recording aside (for example to `failed-recordings/`) so replay never uses it. The scripted
cassettes are regenerated by their scenario tests: `mvn -pl orchestrator test -Dscenarios=true
-Dtest=BrownfieldScenarioTest -Dbrownfield.cassette.out=scenarios/brownfield/cassette.jsonl` (likewise
`AmbiguousScenarioTest` with `-Dambiguous.cassette.out=...`, and `RecordReplayTest` with
`-Dsmoke.cassette.out=...`).

**When to re-record**: after changing a prompt, a model setting, the codebase analysis, or a scenario's
starting code (including `shortener/`, which the ambiguous scenario starts from and the brownfield
template mirrors). The default build tells you: the cassette tests fail.

## Alerts

`ops/prometheus/alerts.yml`:

| Alert | Meaning | First action |
| --- | --- | --- |
| `AuditChainBroken` | An audit log no longer verifies | Stop trusting that run's evidence; run `verify-evidence` to find the first bad event |
| `ApprovalWaitingTooLong` | A run has waited 30 minutes for a human | Review it in the console, or safe-stop it |
| `GateFailureRateHigh` | More than 20% of gate evaluations fail | Look for a prompt or model change; compare with the last eval |
| `ClicksDropped` | The shortener's click queue was full | Statistics under-count; check database write latency |
| `LinkCacheErrors` | Redis errors | Redirects still work from the database; check Redis |
| `RedirectLatencyHigh` | p99 redirect latency above 50 ms | Check cache hit rate and database |

## Troubleshooting

| Symptom | Cause | Fix |
| --- | --- | --- |
| `cassette miss: re-record this scenario` | A prompt, model setting, starting code or typed answer differs from the recording | Re-record, or use the recorded wording; in the console, typed clarifications need live mode |
| `detected dubious ownership in repository` | Run directories on a mounted volume owned by another user (Docker Desktop) | Fixed in the image and in every git call (`safe.directory`); rebuild with `--build` |
| Build fails with `Input/output error`, or files named `Something 2.class` | A sync client (iCloud Desktop & Documents, OneDrive) copies files while Maven writes them | The test services keep build output on Docker volumes; best: keep the project outside synced folders |
| A test reads `.DS_Store` | Finder metadata | Ignored by workspaces and tests; it is in `.gitignore` |
| `API key not scoped to workspace` | The key belongs to a workspace | `export ANTHROPIC_WORKSPACE_ID=...` |
| `temperature is deprecated` | A model setting sends temperature | Remove `temperature` from that agent's settings |
| `the answer was cut off at the N-token output limit` | Thinking plus answer exceeded the cap | Raise that agent's `max-tokens`, or narrow the task |
| `merge conflict while preparing 'integrate'` | Two parallel nodes changed the same file | Plan problem: shared files belong to the design node; reject the plan with that feedback |
| Console port 8080 in use | Another process | `docker compose run --service-ports` with another mapping, or stop it |
| First run slow | Maven dependency download | Later runs reuse `./.m2` |
